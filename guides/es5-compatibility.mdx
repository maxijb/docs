BitSetJS is distributed with two builds: the default ES6 source in `lib/BitSet.js` and an ES5-compatible alternative in `lib/BitSetES5.js`. Both files expose exactly the same public API — the ES5 build exists solely to widen the range of environments you can target. If you are deploying to older browsers, supporting a legacy enterprise intranet, or running BitSetJS inside an environment that does not support ES6 syntax, reach for the ES5 build. In every other situation you can rely on the default.

## When to use the ES5 build

Use `lib/BitSetES5.js` when your environment does not fully support ES6. Common scenarios include:

<CardGroup cols={2}>
  <Card title="Legacy Browsers" icon="globe">
    Browsers such as Internet Explorer 11 do not support arrow functions, `const`/`let`, or default function parameters. The ES5 build removes all of these and works without a transpilation step.
  </Card>
  <Card title="Legacy Node.js" icon="server">
    Node.js versions older than 6.x have incomplete ES6 support. If you are maintaining an application on an end-of-life Node.js release, the ES5 build avoids syntax errors at require time.
  </Card>
  <Card title="Embedded or Constrained Runtimes" icon="microchip">
    Some headless browsers, WebViews, and embedded JavaScript engines (e.g., older versions of JavaScriptCore in mobile apps) implement only ES5. The ES5 build targets the lowest common denominator.
  </Card>
  <Card title="No Build Toolchain" icon="code">
    If you are loading the script directly in HTML without webpack, Rollup, or any transpiler, the ES5 build is the safest drop-in choice for maximum compatibility.
  </Card>
</CardGroup>

## Loading the ES5 build

<Steps>
  <Step title="In a Node.js or CommonJS context">
    Reference the file path directly instead of using the package name. The package name always resolves to the ES6 build via the `main` field.

    ```javascript
    // Require the ES5 build by path
    const BitSet = require('bit-set-js/lib/BitSetES5');

    const flags = new BitSet(32);
    flags.set(7);
    console.log(flags.stringify()); // "00000000000000000000000010000000"
    ```

    If you keep BitSetJS as a vendored file (copied into your project rather than installed via npm), adjust the path to wherever you placed `BitSetES5.js`.
  </Step>

  <Step title="In an HTML page via script tag">
    Place the `<script>` tag before any code that uses `BitSet`. The library will assign itself to `window.BitSet` automatically when it detects a non-CommonJS environment.

    ```html
    <!-- Load the ES5 build directly -->
    <script src="node_modules/bit-set-js/lib/BitSetES5.js"></script>

    <script>
      // window.BitSet is now available
      var flags = new BitSet(16);
      flags.set(0);
      flags.set(4);
      console.log(flags.stringify()); // "0000000000010001"
    </script>
    ```
  </Step>
</Steps>

## API compatibility

The ES5 build is a direct Babel-compiled translation of the ES6 source. Every public method and property is present and behaves identically. You can swap between the two builds without changing a single line of application code.

<CodeGroup>
```javascript ES6 build (lib/BitSet.js)
const BitSet = require('bit-set-js');

const bs = new BitSet(8);
bs.set(1);
bs.set(5);

console.log(bs.get(1));       // true
console.log(bs.get(3));       // false
console.log(bs.toggle(3));    // true (operation succeeded)
console.log(bs.count());      // 3
console.log(bs.stringify());  // "00101010"

bs.clear(1);
console.log(bs.count());      // 2

bs.invert();
console.log(bs.count());      // 6
```

```javascript ES5 build (lib/BitSetES5.js)
var BitSet = require('bit-set-js/lib/BitSetES5');

var bs = new BitSet(8);
bs.set(1);
bs.set(5);

console.log(bs.get(1));       // true
console.log(bs.get(3));       // false
console.log(bs.toggle(3));    // true (operation succeeded)
console.log(bs.count());      // 3
console.log(bs.stringify());  // "00101010"

bs.clear(1);
console.log(bs.count());      // 2

bs.invert();
console.log(bs.count());      // 6
```
</CodeGroup>

The full public API available in both builds:

| Method / Property | Description |
|---|---|
| `length` | Number of bits in the BitSet |
| `set(n)` | Sets bit `n` to `1`. Returns `true` on success, `false` if `n` is out of range |
| `get(n)` | Returns `true`/`false` for the bit at `n`, or `null` if out of range |
| `clear(n)` | Sets bit `n` to `0`. Returns `true` on success |
| `toggle(n)` | Flips bit `n`. Returns `true` on success |
| `invert()` | Flips every bit in the set. Returns the BitSet instance |
| `count()` | Returns the number of bits currently set to `1` |
| `getData()` | Returns the backing array of 32-bit integers |
| `toArray()` | Returns an array of `0`/`1` values, one per bit |
| `stringify()` | Returns a binary string (`"01101..."`) — rightmost character is bit 0 |
| `toString()` | Returns `"[object BitSet]"` for type identification |

## Default build

When you install the package and write `require('bit-set-js')`, Node.js reads the `main` field in `package.json` and loads `lib/BitSet.js` — the ES6 build. The ES5 build is **not** loaded by default and must always be referenced by its explicit file path.

```javascript
// Loads lib/BitSet.js  (ES6 — the default)
const BitSet = require('bit-set-js');

// Loads lib/BitSetES5.js  (ES5 — explicit path required)
const BitSet = require('bit-set-js/lib/BitSetES5');
```

If you want to default to the ES5 build throughout a project, consider aliasing the path in your module bundler (e.g., webpack's `resolve.alias`) rather than scattering the long file path across your codebase.

<Warning>
  Only switch to the ES5 build when you genuinely need it. Modern JavaScript engines — including current versions of V8 (Node.js, Chrome), SpiderMonkey (Firefox), and JavaScriptCore (Safari) — optimize ES6 constructs such as `const`, arrow functions, and default parameters more aggressively than their transpiled ES5 equivalents. Using the ES5 build in a modern environment sacrifices performance for no benefit.
</Warning>
